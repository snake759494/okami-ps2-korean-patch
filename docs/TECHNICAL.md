# 기술 설명

## 디스크 구조

| 항목 | 내용 |
| --- | --- |
| 실행파일 | `SLPM_663.75` |
| 아카이브 | `_DATA0.AFS`, `_DATA1.AFS` (항목 3,932개, 이름표 포함, 중복 이름 있음 → 항목 번호로 구분) |
| 파일 표 | `WOLVES.FST`: 64비트 레코드(종류, 64바이트 단위 크기, 이름 오프셋, AFS 전역 항목 번호). 위치 정보는 없음 |
| 공통 컨테이너 | `u32 개수, u32 오프셋[개수], 4바이트 태그[개수]`, 16바이트 정렬, 중첩 |

## 메시지

블록마다 **MSD**(본문)·**MSA**(글자 정보)·**MST**(글자 텍스처)가 한 묶음입니다.

- MSD: `u16 개수, u16 미상, (u32 본문, u32 루비) × 개수`. 문자는 u16. `0x8000` 이상은 명령이며 하위 바이트가 워드 길이(`0x8001` 끝, `0xA001` 줄바꿈, `0xA301` 입력 대기, `0xA101` 페이지 지우기). 루비(후리가나)는 `(위치, 본 글자 수, 가나 수, 가나…)` 목록, `0xFFFF` 끝.
- 글자 번호: 상위 4비트가 뱅크. 0 = 공용 글꼴(core.bin, 718자), 2 = 방 대사 블록 글꼴, 3 = 메뉴 블록 글꼴. 하위 12비트가 블록 안 번호.
- MSA: `u16 글자 수, u16 폭, u16 높이, u8 칸 폭, u8 칸 높이` + 글자마다 4바이트(잉크 상자 x0·y0·x1·y1, 6비트씩).
- MST: TIM3 4bpp. 한 칸에 2비트 글자 두 장(논리 번호 `i ^ 1` 관계). 128×128 이상은 PSMCT32 업로드 스위즐, 그보다 작으면 선형.
- 도감 PAC 4개는 레코드가 고정 간격(20,480 / 12,288바이트)으로 배치됩니다.
- 일부 메뉴 파일(`idsg*`, `idwarp`, core.bin 등)은 `TBL` 표 안에 MSD/MSA/MST PAC 이 들어 있어 일반 컨테이너 순회로는 보이지 않습니다(`tools/extract_missed.py`).

## 한글화 방식

1. 공용 글꼴 718칸을 자주 쓰는 한글로 채우고, 블록마다 나머지 음절을 블록 글꼴에 배치합니다. 한국어 `… ! ? 「 」 0-9 ( ) · ━` 는 원본 기호 글리프를 그대로 씁니다.
2. 글리프는 서울한강체 B 22px 를 26×26 칸에 그립니다. 세로 위치는 한글 기준선으로 고정해 쉼표·마침표가 아래에 붙습니다.
3. 번역문은 원문과 같은 제어 토큰 순서를 유지합니다(줄바꿈·페이지 토큰만 자동 줄바꿈에서 재배치).
4. 블록 크기가 바뀌면 컨테이너를 다시 조립하고, AFS 를 재배치한 뒤 `WOLVES.FST` 크기 필드, ISO9660 디렉터리(양쪽 엔디언), 볼륨 크기를 갱신합니다.
5. `TBL` 안의 PAC 과 고정 레코드는 원래 크기를 넘지 않게 합니다(필요하면 작은 텍스처·작은 칸 사용).
6. 글자 그림은 크기·팔레트를 유지한 채 인덱스만 바꿉니다. 같은 그림의 중복 사본은 바이트 일치로 모두 찾아 바꿉니다.

## 검증

- 무변경 재조립 ISO 가 원본과 SHA-256 동일.
- 빌드 결과를 다시 읽어 AFS 3,932항목·FST·ISO 디렉터리 일치 확인, 메시지·글꼴 왕복 변환 검사.
- PCSX2 로 타이틀, 새 게임 도입부, 메뉴, 도감 화면을 확인.
